# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The project is pre-1.0 and has
not been released yet, so everything below is still subject to change.

## [Unreleased]

### Added

- Repository scaffold: `project.yml` describing the tvOS app target and the shared `AniLibertyKit`
  package, with the Xcode project generated by XcodeGen instead of being committed.
- `AniLibertyKit` Swift package skeleton (`Package.swift`, library + test targets, Swift 6 language
  mode, tvOS 26.0 / iOS 18 / macOS 14 platforms, no third-party dependencies).
- Public API contract for the Kit in `docs/SCAFFOLD_CONTRACT.md`, including the symbols the app is
  allowed to use and the fixture-backed test strategy.
- Linting and formatting configuration: `.swiftlint.yml` (opt-in force-unwrap, implicit-unwrap and
  modern-Swift rules; 120-character lines; `swiftlint --strict` clean) and `.swiftformat` (minimal
  option set verified against SwiftFormat 0.64.6, `--swift-version 6.0`). Modifier ordering is owned
  by SwiftFormat; SwiftLint's `modifier_order` rule is disabled because the two tools demand opposite
  orders and the linter cannot be configured otherwise (ADR 0010).
- GitHub Actions CI (`.github/workflows/ci.yml`): generates the project with XcodeGen, builds the
  app for the tvOS Simulator SDK, runs `swift test --package-path AniLibertyKit`, then
  `swiftformat --lint .` and `swiftlint --strict` on pull requests and pushes to `main`, with pinned
  SwiftFormat/SwiftLint versions and cached Swift Package Manager artifacts.
- `.gitignore` covering generated Xcode project files, the XcodeGen-generated `App/Info.plist`,
  build output, derived data, test results, user-specific Xcode state and signing/secret material.
- Project documentation: `README.md` (what the app is, unofficial disclaimer, feature status, build
  and test instructions, architecture map), `CONTRIBUTING.md` (workflow, memory protocol, commits,
  definition of done, why the project and `Info.plist` stay out of git), `SECURITY.md` (private
  vulnerability reporting, Keychain-only session token policy, scope) and `AGENTS.md` (working
  agreement for humans and AI agents).
- Project memory files: `docs/PROJECT_MEMORY.md` (living state), `docs/DECISIONS.md` (decision log
  with ADRs 0001-0009) and `docs/api-notes.md` (verified API facts).
- MIT `LICENSE` (ADR 0008).
- `AniLibertyKit` implementation: models mirroring the API (`Release`, `Media`, `Episode`, `Genre`,
  `NamedValue`), an `AniLibertyClient` on top of a hand-written `HTTPTransport` with typed
  `AniLibertyError` mapping, a shared `JSONDecoder` configuration, an actor-based image cache and
  player helpers (`StreamResolver`, `TimecodeResolver`). Covered by 25 fixture-backed tests.
- tvOS app on top of the Kit: Liquid Glass tab shell (Новинки / Каталог / Профиль), a "Новинки" screen
  that loads `GET /anime/releases/latest` and renders a six-column poster grid with loading, empty and
  error states, a release detail screen with the episode list, and an `AVPlayerViewController`-based
  player screen with external metadata and resume handling.
- Design system shared by the screens: background, design tokens, glass badge, rating pill, remote
  image view backed by the Kit cache, screen header and a wrapping layout.
- Localisation catalog with 44 keys (English source, Russian translations) and an asset catalog with
  an accent colour.
- App icon and static Top Shelf image as a tvOS `App Icon & Top Shelf Image` brand assets collection:
  a two-layer icon (`Back` plate + `Front` mark, 400×240 and @2x) and Top Shelf artwork at 1920×720
  and 2320×720 carrying the product name and the "неофициальный клиент" note. The mark is taken from the official Android TV app, which is recorded with its
  GPL-3.0 provenance and trademark caveat in `docs/THIRD_PARTY_ASSETS.md` (ADR 0017).
- XCUITest suite (`App/UITests/LatestFeedUITests.swift`, target `AniTVUITests`) that drives the focus
  engine through `XCUIRemote`: it opens a release from the feed, checks the detail screen describes the
  selected title, starts playback from the detail screen and returns through Menu. Screenshots of the
  feed, detail and player screens are kept as test attachments and published in `docs/screenshots/`.
- Accessibility identifiers for the elements the tests address (`latest.posterCard`, `detail.screen`,
  `detail.playButton`, `detail.synopsisToggle`, `detail.episodeCard`, `player.screen`).
- Episode list on the release detail screen is a two-column grid of episode cards with preview,
  title, duration and the best available quality; picking one starts exactly that episode in the
  player.
- Quality switching in the player, as a native transport-bar entry: the button carries the running
  quality ("1080p") and opens the system «Качество» menu with every stream the episode publishes
  (1080p / 720p / 480p). It is visible exactly as long as the transport bar is, never permanently over
  the video. Switching replaces the player item and keeps the playhead (ADR 0016, superseding
  ADR 0014).
- «Профиль» works end to end against a real account: pairing code → confirmed on the site → profile
  (display name, login, avatar) → favourites page → «Выйти» back to a fresh pairing code. Four defects
  on the way were fixed from logs: account calls need a clean session, every refusal while polling means
  "keep waiting", re-issued codes are polled as a set, and the profile request must leave the cancelled
  polling task (ADR 0022).
- «Каталог» tab: search over the catalogue, single-choice filters for genre, type, year and sorting
  (each behind a modal picker that shows the active choice on its chip), a result counter, paging with
  «Показать ещё» and reset. Search debounces at 400 ms; the screen reuses the poster grid and pushes
  the same release detail screen as the «Новинки» tab.
- Episode cards in the style of the official site: a three-column grid of full-bleed previews with a
  scrim, the episode title over the still, «N эпизод» with the number in bold and the length in a pill
  in the corner; episodes without a stream stay dimmed and disabled.
- «Смотреть» now opens a modal episode picker (same card style, focus on the episode the player would
  have picked, Menu closes it without playing) instead of jumping straight into the first stream.
- Playback progress memory: the player stores the position of the current episode every five seconds
  and once more when it is dismissed, and the release screen offers «Продолжить» to the left of
  «Смотреть» when that position is worth resuming (past the first 15 s and not inside the last 30 s).
  The store lives in the Kit (`PlaybackProgress`, `PlaybackProgressStoring`,
  `PlaybackProgressStore`, 17 tests, one record per release, `UserDefaults`).
- Two more UI-test scenarios (`DetailAndPlayerUITests`): scrolling the detail screen down to the
  episode list and playing an episode from it, and switching the stream quality through the chooser.

### Changed

- CI "Show the toolchain" step now queries `xcrun --sdk appletvos`, the real SDK name; `tvos` does not
  exist and the old command failed with `SDK "tvos" cannot be located`.
- CI and `CONTRIBUTING.md` build against `generic/platform=tvOS Simulator` instead of a named simulator,
  so the pipeline does not depend on device names in the runner image.
- Error-to-`AniLibertyError` mapping lives once in `App/Sources/Support/AniLibertyError+Mapping.swift`
  instead of being duplicated in two view models.
- The player no longer draws its own title badge over the video: the system info panel already shows
  the release, the episode and the stream, and the badge only duplicated it (and could not be hidden).
- The player's in-screen title badge and its floating quality pill are gone: quality now lives in the
  system transport bar as a single `UIMenu` entry. A flat list of `UIAction`s in the same place is
  rendered as unlabelled circles the focus engine never reaches, while one `UIMenu` becomes a real
  button that opens the system menu (ADR 0016, superseding ADR 0014).
- The episode list is built with the eager `Grid` instead of `LazyVGrid`: the first row sits below the
  fold, so no cell was ever instantiated, nothing was focusable, and focus could never scroll down to
  a list that therefore never materialised.
- The release detail screen waits for the release (and with it the resume decision) before it takes
  focus, so a release with saved progress opens with «Продолжить» focused instead of «Смотреть». The
  UI tests accept either hero action, because both are correct depending on the stored progress.
- The release detail screen claims focus for its primary action when it appears. Without that, the
  focus engine had nothing to focus after the push, and a Menu press was handled by the system, which
  backgrounded the app instead of popping back to the feed (ADR 0012).
- CI pins every tool it installs (XcodeGen 2.46.0 from a release archive instead of Homebrew,
  xcbeautify 3.2.1, SwiftFormat 0.64.6, SwiftLint 0.65.1) and gains an advisory `ui-tests` job that
  runs the XCUITest suite on a tvOS simulator, discovered by UDID rather than by device name.

### Fixed

- Menu on the release detail screen sent the app to the home screen instead of returning to the feed,
  because the pushed screen had no focused element (ADR 0012).
- The release detail screen could not be scrolled at all: `.scrollClipDisabled()` made the scroll view
  report its whole content as visible, so Down presses never left the hero and genres, synopsis and
  the episode list were unreachable dead content (ADR 0015).
- The hero poster on the release detail screen was sliced horizontally: it was given a width-only
  frame while the image view fills whatever frame it gets, so the artwork was cropped to a narrow
  strip. Both dimensions now come from the 2:3 poster ratio.

### Security

- No secrets in the repository, by design: CI runs on GitHub-hosted runners with no configured
  secrets, and the user's AniLiberty token is stored only in the Keychain on the device.
